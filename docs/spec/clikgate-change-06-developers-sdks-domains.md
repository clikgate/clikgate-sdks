### B.1 Device sign-in for the setup command (RFC 8628)
**cli_device_codes**
- id (`cdc_`), device_code_hash (SHA-256), user_code (8 characters from `BCDFGHJKLMNPQRSTVWXZ23456789`, shown as `ABCD-EFGH`; unique among unexpired codes), client_info (jsonb: `cli_version`, `os`, `hostname_hint` (the first 32 characters of the hostname, for display only), `project_type`), status (`pending|approved|denied|expired|consumed`), approved_by_user_id, organization_id, created_at, expires_at (10 minutes), approved_at, last_polled_at.

**cli_sessions**
- id (`cls_`), user_id, organization_id, token_hash, prefix (first 12 characters), client_info, created_at, expires_at (1 hour), last_used_at, revoked_at.
- Token format `cg_cli_<random>`, returned once, never stored in plain text; the command keeps it **in memory only**.

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/v1/cli/device-codes` | none; rate-limited (10 per hour per IP) | `{client_info}` → `{device_code, user_code, verification_uri, verification_uri_complete, expires_in: 600, interval: 5}`. `verification_uri` = `https://app.clikgate.com/cli` |
| POST | `/v1/cli/token` | none | `{device_code}` → `428 authorization_pending`, `429 slow_down`, `403 access_denied`, `410 expired_token`, or `200 {access_token, expires_in, organization: {id, name}}`. A code can be exchanged **once** |
| GET | `/v1/cli/device-codes/{user_code}` | dashboard user | For the approval page: client info, expiry, status. 404 if expired or unknown |
| POST | `/v1/cli/device-codes/{user_code}/approve` | dashboard user with `apps:manage` in the chosen org | `{organization_id}` → approved |
| POST | `/v1/cli/device-codes/{user_code}/deny` | dashboard user | Denied |
| GET | `/v1/cli/sessions` | dashboard user | Active sessions in the current org |
| POST | `/v1/cli/sessions/{id}/revoke` | own sessions, or `org:manage` | Revoke |

- Viewers can't approve ("You need developer access to approve this").
- Five wrong `user_code` entries per user per 10 minutes → locked for 10 minutes.
- Audit log: `cli.authorized`, `cli.denied`, `cli.revoked`, and every write made with a CLI token (actor type `cli`, with the approving user).

### B.9 Faster custom subdomain setup
**One record for subdomains.** Each customer subdomain gets its own CNAME target: `<domain_key>.links.clikgate-edge.net`, where `domain_key` is a short random string stored on the domain (served by a wildcard record on Clikgate's side). Because only someone controlling the customer's DNS can point their name at that unique target, the CNAME also **proves ownership**: the separate TXT ownership record is no longer required for subdomains. Bare domains still use A/AAAA (or ALIAS) records plus the TXT ownership record, because A records aren't unique per customer. Update the Part 3 `setup` object accordingly: `records[]` with `{type, name, value, purpose, status}` per record.

**Connect automatically (Domain Connect).** Implement Clikgate as a Domain Connect service provider:
- A template (`providerId: clikgate.com`, `serviceId: linkdomain`) that adds the CNAME (subdomains) or A/AAAA records (bare domains). Submit it to the public Domain Connect templates repository and follow each DNS provider's onboarding; record which providers accept it.
- Discovery: look up the `_domainconnect` TXT record of the customer's domain, then the provider's settings endpoint. If supported, `setup.connect_automatically = {provider_name, apply_url}`; the apply URL uses the synchronous flow with signed parameters (private signing key stored as a secret; public key published per the protocol).
- After the provider redirects back, start live checks immediately.

**Instructions for the customer's DNS provider.** Detect the provider from the domain's NS records (a mapping kept in config) and return `setup.provider = {key, name, guide_url}`. Guides exist on the website for Whogohost, Qservers, Web4Africa, GoDaddy, Namecheap, Cloudflare DNS, AWS Route 53 and Azure DNS (W.4); unknown providers get the general guide.

**Live checks.** `GET /v1/domains/{id}/setup` re-checks on request, at most every 10 seconds per domain, querying the domain's **authoritative nameservers directly** (not public resolvers that cache old answers). Certificate issuance starts as soon as the record is found.

**Mistake detection.** The setup response includes `problems[]` with codes, a plain explanation and the exact fix:
- `existing_record_conflict`: another A, AAAA or CNAME record exists at that name (show it and say to remove it);
- `proxied_by_customer_cloudflare`: the record resolves to Cloudflare addresses instead of the target because the customer's own Cloudflare proxy is on (say to switch the record to "DNS only");
- `caa_blocks_certificate`: a CAA record forbids the certificate authorities Clikgate's provider uses (show the exact CAA records to add);
- `target_typo`: the CNAME points to something close to, but not exactly, the target (show found vs expected);
- `not_found_yet`: nothing yet (say DNS can take time, keep checking).

**Send to my IT team.** `POST /v1/domains/{id}/send-setup` `{email, note?}` (scope `domains:manage`; 5 per day per domain; audit-logged):
- Sends an email (change 04 templates) with the record(s) as a table, a **read-only live status link** (`https://app.clikgate.com/domain-setup/<signed token>`, valid 14 days, no sign-in, shows the records and live check results only), and a **one-page change-request PDF** (change 04 renderer).
- The PDF contains: what the record is for; the exact record; what Clikgate will serve on that name (redirects only, HTTPS with HSTS, TLS 1.2+); what Clikgate never receives (the organisation's website traffic, cookies or logins); how to undo it (delete the record); the reminder to remove the record if the organisation ever stops using Clikgate; Clikgate's security contact and trust centre link.

**Switching from another provider without downtime.** On add, the customer can tick "This name already serves links elsewhere (e.g. Branch or AppsFlyer)". The setup then shows the certificate **pre-validation** record (from Cloudflare for SaaS) first; once the certificate is issued, it shows "Ready to switch: change the CNAME now", so links never break.

**Leaving and dangling records.** When a customer domain is removed, or an organisation leaves (change 03), Clikgate emails the owners to remove the DNS record, shows the warning in the dashboard, and checks weekly for 90 days; while the record still points to Clikgate, the name serves only the "Link not available" page and can't be claimed by another organisation.

### B.10 Link safety
**Transport security on every link domain**
- `Strict-Transport-Security: max-age=31536000; includeSubDomains` on `ciz.to`, `clk.ng` and `clkg.to` (consider HSTS preload for these platform domains and record the decision); `max-age=31536000` (no `includeSubDomains`, no preload) on customer domains, because Clikgate doesn't control their other subdomains.
- Minimum TLS 1.2 on every hostname.
- Redirect responses carry `Referrer-Policy: strict-origin-when-cross-origin` by default and `no-referrer` for regulated organisations.

**Organisation link-safety settings** (`organizations.settings.link_safety`, `org:manage`):
```json
{
  "https_only_destinations": false,
  "destination_allowlist_required": false,
  "lock_new_links": false,
  "destination_change_approval": "off",
  "clikgate_pages": {"ios_interstitial": true, "link_preview_plus": true}
}
```
- **Regulated organisations:** a flag `organizations.regulated` set by staff (🔐) or automatically when private mode (change 05) is switched on. Regulated defaults: HTTPS-only destinations on, allowlist required, two-person approval on, iOS interstitial and `+` link preview off. The organisation can change them, with a warning and an audit entry.
- **Destination allowlist** (existing feature): when `destination_allowlist_required` is on, live links can only point to allowlisted domains (`422 destination_not_allowlisted`).
- **Locked links:** `links.locked` (bool), `locked_by`, `locked_at`. Destination, fallback and deep-link changes on a locked link return `409 link_locked`. Unlocking needs `org:manage` and is audit-logged. `lock_new_links` locks every new link automatically.
- **Two-person approval:** when `destination_change_approval = "two_person"`, a destination change creates a **link_change_requests** row (id `lcr_`, link_id, requested_by, from_url, to_url, status `pending|approved|rejected|expired`, decided_by, decided_at, created_at, expires after 7 days) and the API returns `202` with the request. Another user with `org:manage` approves or rejects (`POST /v1/link-change-requests/{id}/approve|reject`); the requester can't approve their own. API keys can request but never approve.
- **Alerts on every destination change:** webhook `link.destination_changed` (from, to, actor, actor type, API key prefix when relevant), an email to organisation owners and admins (digest if more than 5 in 10 minutes), and an in-app alert.
- **Staff can't edit customer links.** No staff endpoint changes a link's destination, fallback or deep link; staff abuse actions (change 03) only pause or flag. Add a test that scans the staff routes.

### B.11 Link preview warning
Link create and update responses include `warnings: [{"code": "no_preview", "message": "Add a preview title and image. In WhatsApp and social apps, people look at the preview more than the link."}]` when both `og_title` and `og_image_url` are empty. It never blocks the request.

#### S.3 Setup flow

2. **Check the working tree:** uncommitted git changes → warn and ask; not a git repository → back up every changed file to `.clikgate-setup-backup/<timestamp>/`.
3. **Sign in:** request a device code and print:

4. **Pick the Clikgate app(s):** read Android `applicationId` and iOS `PRODUCT_BUNDLE_IDENTIFIER` / `DEVELOPMENT_TEAM` (ask when ambiguous; Expo reads `android.package` and `ios.bundleIdentifier`), match existing apps, or offer to create them.

8. **Show and confirm:**

10. **Verify:** run `doctor` (S.5) and ask the person to run the app on a device or emulator: "Waiting for the first event from your app… (up to 5 minutes, press Enter to skip)".
11. **Summary:** done, skipped and manual steps; reminders; next steps (create a link; "go live": switch to the live SDK key for release builds, with the exact line to change and a dashboard link; the command never handles the live key). Final line: **"Clikgate sees every click. Setup complete."**

**Money:** `value` is always in normal units (₦2,000,000 = `2000000`) and is always sent as a **decimal string**. Node accepts `string | number | bigint` (warns on inexact numbers); Python `Decimal | int | str` (a `float` raises `TypeError`); PHP `string | int` (a `float` throws in strict mode); Java `BigDecimal` or `long`; .NET `decimal`.

#### S.11 Errors
- Typed errors from the error envelope: `AuthenticationError`, `PermissionError`, `InvalidRequestError` (with `param`, `code`), `NotFoundError`, `ConflictError` (including `link_locked`), `IdempotencyError`, `RateLimitError` (`retryAfter`), `PrivateModeFieldRejectedError` (field name only), `ServerError`, `NetworkError`, `TimeoutError`; all extend `ClikgateError` with `requestId`, `httpStatus`, `code`.
- Sync calls throw; **background `goal()` never throws** into the business's code (failures go to `logger` and `onError`, reference masked in private mode).
- Configuration errors throw at construction.

#### S.12 Sending modes, retries and idempotency
- **Background** (default except PHP): an in-memory queue (10,000; when full, the oldest event is dropped and logged); batches via `/v1/goals/events/batch` every 1 s or 100 events; `flush(timeout)` and `close(timeout)`; automatic flush on shutdown (Node `beforeExit`/`SIGTERM`, opt-out; Python `atexit`; Java shutdown hook and Spring lifecycle; .NET `IHostedService` / `DisposeAsync`). Serverless docs: `await clikgate.flush()` before returning, or `sendMode: 'sync'`.
- **PHP** defaults to sync; `sendMode: 'after_response'` sends after `fastcgi_finish_request()` when available; Laravel can send through a queued job (`CLIKGATE_QUEUE=redis`, recommended).
- **Retries:** network errors, timeouts, `429` (respect `Retry-After`), `500`, `502`, `503`, `504`; exponential backoff with full jitter (base 0.5 s, cap 20 s); never other 4xx.
- **Idempotency:** goals send `Idempotency-Key = sha256(goal + ":" + reference)`; other POST/PATCH calls reuse one random key across their retries. A retry never double counts.

#### S.13 Quality bar (all five SDKs)
- **Cross-language conformance suite** (`sdks/server/conformance/`): language-neutral JSON cases (inputs → expected HTTP request; mocked responses → expected result or error; retry sequences; idempotency keys; webhook signatures valid, expired, tampered and rotated; click-ID extraction; private-mode rejections; money formatting; link change-request and locked-link responses). Each SDK has a runner against a local mock server. **A case that passes in one SDK must pass in all five.**
- **Nightly live contract tests** against the real test environment with a `cg_test_` key (goal, duplicate, reverse, batch, links CRUD, webhook round trip).
- **Typed:** Node TypeScript-first (ESM + CJS + `.d.ts`); Python full hints, `py.typed`, mypy strict, sync `Clikgate` and async `AsyncClikgate`; PHP `strict_types`, PHPStan max; Java nullability annotations, Kotlin-friendly; .NET nullable reference types, async-first.
- **Few dependencies:** Node zero; Python `httpx` only; PHP PSR interfaces + `php-http/discovery`; Java Jackson databind only (declared, not shaded); .NET none on .NET 8, `System.Text.Json` on .NET Standard 2.0.
- **Thread-safe clients**; docs say "create one client and reuse it".
- **CI matrix:** every officially supported runtime version plus the minimums in S.9, on Linux and Windows.
- **For regulated customers:** CycloneDX SBOM per release; signed artifacts and provenance (npm provenance, PyPI attestations, Maven GPG signatures and checksums, NuGet signing); dependency scanning; `SECURITY.md` with the trust-centre disclosure address; no telemetry beyond `User-Agent`.
- **Versioning:** semantic versioning, a changelog per SDK, deprecations announced at least 6 months ahead, runtime support dropped only after that runtime's end of life.
- **Docs in code:** doc comments with an example on every public method.
- **Examples** in `sdks/server/<lang>/examples/` (Express, Next.js, Django, FastAPI, Laravel, Spring Boot, ASP.NET Core minimal API): capture → save → send goal → verify webhook.

#### S.14 Keeping the click ID
- **Core helpers:** `clickIds.fromRequest(request)` (query parameter `{clickIdParam}`, then cookie `_cg_{clickIdParam}`, then header `Clikgate-Click-Id`; only values matching `^clk_[0-9A-Z]{26}$`); `clickIds.isValid(id)`; `clickIds.persist(response, id, {days: 30})` (same first-party cookie as the web script: `SameSite=Lax`, `Secure` on HTTPS, readable by the web script); `clickIds.fromPaymentMetadata(payload)` (Paystack `metadata`, Flutterwave `meta`, Shopify attributes, WooCommerce order meta).
- **Framework add-ons:**

  | Framework | Usage | Exposes |
  |---|---|---|
  | Express / Connect | `app.use(clikgateMiddleware(clikgate))` | `req.clikgate.clickId` |
  | Fastify | `fastify.register(clikgatePlugin, { client })` | `request.clikgate.clickId` |
  | Next.js | `export { clikgateMiddleware as middleware }` from `@clikgate/node/next`; `getClickId(cookies())` | — |
  | Django | `clikgate.django.ClikgateMiddleware` | `request.clikgate_click_id` |
  | Flask | `Clikgate(app)` | `g.clikgate_click_id` |
  | FastAPI / Starlette | `app.add_middleware(ClikgateMiddleware)`; `Depends(click_id)` | — |
  | Laravel | auto-discovered provider, `clikgate` middleware alias, `Clikgate` facade, `config/clikgate.php` | `$request->clikgateClickId()` |
  | PSR-15 | `ClikgateMiddleware` | attribute `clikgate.click_id` |
  | Spring Boot | starter auto-configures from `clikgate.*` properties plus a servlet filter | `@ClikgateClickId String clickId`, `ClikgateContext.currentClickId()` |

#### S.15 Private-mode guard
When private mode is on (`privateMode: 'auto'` from config, or `true`), the SDK checks every goal and conversion **before sending**: only `goal`, `clickId`, `code`, `reference`, `value`, `currency`, `isFirst` and `occurredAt` are allowed; anything else is refused locally with `PrivateModeFieldRejectedError`. References are masked in SDK logs. Tests assert nothing disallowed ever reaches the HTTP layer (capturing transport).

#### S.16 Generated API layer
Generate `clikgate.api.*` from `openapi.json` for each language with one generator (evaluate OpenAPI Generator, Kiota or Speakeasy; record the choice), with templates customised to use the SDK's transport, retries, errors and logging. Hand-written parts (goals, click IDs, webhooks, private mode, links) are what the docs teach; the generated layer is "advanced". CI regenerates on every `openapi.json` change and fails on drift.

## Definition of done
- A developer runs `npx @clikgate/setup` in a Flutter, React Native, Expo, Android or iOS project, approves in the browser, reviews the changes, and sees "Clikgate is receiving events" without editing files by hand; the test domain is only in debug builds.
- An AI coding assistant (Claude Code verified during the build; Cursor and Codex checked by the owner) can set up Clikgate correctly from the published guide.
- A developer installs the Node.js, Python, PHP, Java or C#/.NET SDK and sends a goal in three lines; all five pass the same conformance suite and nightly live tests and ship with SBOMs and signed or provenance-backed releases.
- Paid links use `ciz.to`, free links `clk.ng`, test links `dev.ciz.to` (restricted destinations, limits, expiry, never counted), and staff can move new free links to `clkg.to` in an emergency.
- A customer connects a subdomain with one record, automatically where the DNS provider supports it, sees live checks and plain fixes, can send the setup to their IT team, and can switch from another provider without downtime.
- Link safety settings (allowlist, locked links, two-person approval, alerts, regulated defaults) work, and Clikgate staff can't change customer link destinations.
- The website and docs use the wide layout, show the setup command, SDKs, link domains and link safety, explain `ciz.to`, repeat the brand lines within the placement rules, and contain nothing outdated.
